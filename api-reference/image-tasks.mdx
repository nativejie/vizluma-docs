## 接口

| 操作 | 方法与路径 |
| --- | --- |
| 异步生成图片 | `POST /v1/images/generations/async` |
| 异步编辑图片 | `POST /v1/images/edits/async` |
| 查询任务 | `GET /v1/images/tasks/{id}` |
| 任务列表 | `GET /v1/images/tasks?p=1&page_size=20` |

Base URL：`https://api.vizluma.online/v1`。请求使用 `Authorization: Bearer YOUR_API_KEY`，见 [鉴权与地址](/getting-started/authentication)。

## 请求参数

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `model` | JSON | 是 | 完整模型 ID |
| `prompt` | JSON | 是 | 图片描述或编辑指令 |
| `size` | JSON | 否 | 图片尺寸，如 `1024x1024` |
| `quality` | JSON | 否 | 质量档位，如 `medium`，见 [质量参数](/guides/sizes-and-quality#quality-质量参数) |
| `n` | JSON | 否 | 图片数量，默认 1 |
| `response_format` | JSON | 否 | `url` 或 `b64_json` |
| `Idempotency-Key` | 请求头 | 否 | 同一业务重试使用相同键及请求内容；最长 128 字节，不含换行 |

专用异步地址不需要 `async` 参数或 `Prefer` 请求头。其他生成参数见 [生成图片](/api-reference/images-generations)。

## 提交任务

最小请求只需 `model` 和 `prompt`。

<RequestExample>

```bash async-create.sh
curl --fail-with-body --silent --show-error \
  --connect-timeout 15 --max-time 60 \
  "${VIZLUMA_BASE_URL%/}/images/generations/async" \
  -H "Authorization: Bearer $VIZLUMA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2","prompt":"一只小橘猫，纯白背景，简洁插画"}' \
  -o image-task.json
```

```python Python
import json
import os
from pathlib import Path
from urllib.request import Request, urlopen

base = os.environ.get("VIZLUMA_BASE_URL", "https://api.vizluma.online/v1").rstrip("/")
request = Request(
    base + "/images/generations/async",
    data=json.dumps({
        "model": "gpt-image-2",
        "prompt": "一只小橘猫，纯白背景，简洁插画",
    }).encode("utf-8"),
    headers={
        "Authorization": "Bearer " + os.environ["VIZLUMA_API_KEY"],
        "Content-Type": "application/json",
    },
    method="POST",
)
with urlopen(request, timeout=60) as response:
    task = json.load(response)
Path("image-task.json").write_text(json.dumps(task, ensure_ascii=False), encoding="utf-8")
print(task["id"])
```

```javascript Node.js
// Node.js 20+，保存为 async-create.mjs 后运行。
import { writeFile } from "node:fs/promises";

const base = (process.env.VIZLUMA_BASE_URL || "https://api.vizluma.online/v1").replace(/\/+$/, "");
const key = process.env.VIZLUMA_API_KEY;
if (!key) throw new Error("请先设置 VIZLUMA_API_KEY");

const response = await fetch(base + "/images/generations/async", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${key}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-image-2",
    prompt: "一只小橘猫，纯白背景，简洁插画",
  }),
  signal: AbortSignal.timeout(60_000),
});
if (!response.ok) throw new Error(`HTTP ${response.status}: ${await response.text()}`);
const task = await response.json();
await writeFile("image-task.json", JSON.stringify(task, null, 2), "utf8");
console.log(task.id);
```

</RequestExample>

### 创建响应

HTTP `202`：

```json
{
  "id": "img_example",
  "object": "image.task",
  "model": "gpt-image-2",
  "status": "QUEUED",
  "created_at": 1794300000
}
```

保存顶层 `id` 用于查询。响应头 `X-Image-Task-Id` 也包含该 ID，`Location` 为 `/v1/images/tasks/{id}`。HTTP `202` 表示已接受任务，生成结果通过查询接口获取。

## 异步编辑

将 [图片编辑](/api-reference/images-edits) 的请求地址改为 `/v1/images/edits/async`。JSON 图片链接和 multipart 文件上传参数保持不变，创建响应同上。

## 查询任务

```bash async-status.sh
TASK_ID="img_example"
curl --fail-with-body --silent --show-error \
  --connect-timeout 15 --max-time 60 \
  "${VIZLUMA_BASE_URL%/}/images/tasks/$TASK_ID" \
  -H "Authorization: Bearer $VIZLUMA_API_KEY" \
  -o image-task-status.json
```

建议每 5～10 秒查询一次。

| status | 含义 | 处理 |
| --- | --- | --- |
| `QUEUED` | 已排队 | 继续查询 |
| `IN_PROGRESS` | 正在生成 | 继续查询 |
| `SUCCESS` | 已完成 | 读取 `result.data` |
| `FAILURE` | 失败 | 读取 `response_code` 与 `result.error` |
| `UNKNOWN` | 结果待确认 | 保留任务 ID，继续核查原任务 |

### 成功响应

```json
{
  "id": "img_example",
  "object": "image.task",
  "model": "gpt-image-2",
  "status": "SUCCESS",
  "created_at": 1794300000,
  "finished_at": 1794300035,
  "response_code": 200,
  "result": {
    "created": 1794300000,
    "data": [{"url": "https://static.vizluma.online/new-api/images/IMAGE_OBJECT.png"}]
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 任务 ID |
| `object` | string | 固定为 `image.task` |
| `model` | string | 模型 ID |
| `status` | string | 当前任务状态 |
| `created_at` | integer | 创建时间，Unix 秒 |
| `finished_at` | integer | 完成时间，Unix 秒，完成后返回 |
| `response_code` | integer | 图片请求的 HTTP 状态码，有结果后返回 |
| `result` | object | 原图片响应，有结果后返回 |
| `result.data[].url` | string | 图片链接 |
| `result.data[].b64_json` | string | Base64 图片；按请求的返回格式读取 |

图片下载与 Base64 保存见 [图片结果](/guides/image-results)。

## 任务列表

```bash async-list.sh
curl --fail-with-body --silent --show-error \
  --connect-timeout 15 --max-time 60 \
  "${VIZLUMA_BASE_URL%/}/images/tasks?p=1&page_size=20" \
  -H "Authorization: Bearer $VIZLUMA_API_KEY" \
  -o image-task-list.json
```

返回 `{"object":"list","data":[...],"total":10}`。`p` 为页码，`page_size` 为每页数量。只能查询当前账户的任务；不存在或属于其他账户的任务返回 `404`。

## 重试与兼容

- `Idempotency-Key` 为可选项。同一账户下，相同键和相同请求复用任务；相同键但请求内容不同返回 `409 idempotency_conflict`。
- 未设置幂等键时，每次提交创建新任务。网络重试应保留原键和原请求内容。
- 已取得任务 ID 时，断线或本地等待超时后继续查询原 ID。
- 同步地址仍兼容 `Prefer: respond-async` 和 `?async=true`；与专用异步地址共用任务和幂等规则。
- 异步接口沿用原模型价格，见 [计费说明](/pricing)。

完整创建、轮询与恢复脚本见 [异步生图示例](/guides/async-images)。
