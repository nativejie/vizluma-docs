## 请求

使用 HTTPS 和 JSON 请求体：

```http
POST https://api.vizluma.online/v1/images/generations
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

## 请求示例

<RequestExample>

```bash cURL
curl --fail-with-body --silent --show-error \
  --connect-timeout 15 --max-time 600 \
  "$VIZLUMA_BASE_URL/images/generations" \
  -H "Authorization: Bearer $VIZLUMA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.5-sunburst",
    "prompt": "一只小橘猫坐在纯白色背景上，简洁插画，无文字",
    "size": "1024x1024",
    "quality": "medium",
    "n": 1,
    "response_format": "url"
  }' \

```

```python Python
import json
import os
from pathlib import Path
from urllib.request import Request, urlopen

base_url = os.environ.get(
    "VIZLUMA_BASE_URL", "https://api.vizluma.online/v1"
).rstrip("/")
api_key = os.environ["VIZLUMA_API_KEY"]
payload = {
    "model": "gpt-image-2.5-sunburst",
    "prompt": "一只小橘猫坐在纯白色背景上，简洁插画，无文字",
    "size": "1024x1024",
    "quality": "medium",
    "n": 1,
    "response_format": "url",
}
request = Request(
    f"{base_url}/images/generations",
    data=json.dumps(payload).encode("utf-8"),
    headers={
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    },
    method="POST",
)
with urlopen(request, timeout=600) as response:
    result = json.load(response)

Path("generation.json").write_text(
    json.dumps(result, ensure_ascii=False, indent=2), encoding="utf-8"
)
images = result.get("data", [])
if not images or not all(image.get("url") for image in images):
    raise RuntimeError("未返回有效图片链接，请检查 generation.json")
for image in images:
    print(image["url"])
```

```javascript Node.js
// Node.js 20+，保存为 generate.mjs 后运行 node generate.mjs。
import { writeFile } from "node:fs/promises";

const baseUrl = (
  process.env.VIZLUMA_BASE_URL || "https://api.vizluma.online/v1"
).replace(/\/+$/, "");
const apiKey = process.env.VIZLUMA_API_KEY;
if (!apiKey) throw new Error("请先设置 VIZLUMA_API_KEY");

const response = await fetch(baseUrl + "/images/generations", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-image-2.5-sunburst",
    prompt: "一只小橘猫坐在纯白色背景上，简洁插画，无文字",
    size: "1024x1024",
    quality: "medium",
    n: 1,
    response_format: "url",
  }),
  signal: AbortSignal.timeout(600_000),
});
if (!response.ok) {
  throw new Error(`HTTP ${response.status}: ${await response.text()}`);
}
const result = await response.json();
await writeFile("generation.json", JSON.stringify(result, null, 2), "utf8");
if (!result.data?.length || !result.data.every((image) => image.url)) {
  throw new Error("未返回有效图片链接，请检查 generation.json");
}
for (const image of result.data) console.log(image.url);
```

## quality 质量参数

GPT Image 的生成请求可增加 `quality`。例如：

```json
{
  "model": "gpt-image-2.5-sunburst",
  "prompt": "一只小橘猫，简洁插画，无文字",
  "size": "1024x1024",
  "quality": "medium",
  "n": 1,
  "response_format": "url"
}
```

`quality` 与 `size` 分别设置；省略时使用模型服务默认质量。可选值见 [尺寸与质量参数](/guides/sizes-and-quality#quality-质量参数)。

## 成功响应

HTTP `200`，以下链接为结构占位，不是实际图片：

```json
{
  "created": 1793289600,
  "data": [
    {
      "url": "https://static.vizluma.online/new-api/images/IMAGE_OBJECT.png"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `created` | integer | 结果／任务创建时间，Unix 秒时间戳；不表示生成结束时间 |
| `data` | array | 图片结果列表，遍历每个有效条目 |
| `data[].url` | string | 图片下载链接；使用实际返回值，不拼接固定域名和路径 |
| `data[].b64_json` | string | Base64 图片内容，返回此形式时解码保存 |

`b64_json` 是可选返回方式：将请求的 `response_format` 改为 `b64_json`。服务端实现和响应回退说明见 [图片结果与保存](/guides/image-results)。同步响应体不应假设总有 `usage`、任务 ID 或 `revised_prompt`；异步响应的任务 ID 见下文。

## 执行与结果

- 默认同步等待图片完成，HTTP `200` 返回原有图片结果。
- 需要异步时增加 `Prefer: respond-async`（或 `?async=true`），HTTP `202` 返回任务 ID；使用 [异步生图与任务查询](/api-reference/image-tasks) 获取结果。
- 建议生成和编辑都设置 `Idempotency-Key`；同一业务重试必须保留原键和请求内容，不要让 SDK 自动换键重复提交。
- 不支持客户端要求 SSE 流式生图。
- `n` 大于 1 时需遍历返回数组，不要假设只读取第一项即可。
- 请求超时或断连时结果可能尚不确定，先核对记录，见 [重试说明](/guides/timeouts-and-retries)。

## 错误响应

错误使用非 `2xx` HTTP 状态码。错误消息可能包含请求 ID；不要依赖固定中文或英文字符串判断错误。完整分类见 [错误处理](/api-reference/errors)。
