| 模型 ID | `gpt-6.1-sol` |
| Chat 接口 | `POST /v1/chat/completions` |
| Responses 接口 | `POST /v1/responses` |
| 输出模式 | 完整 JSON 或 SSE |
| 计费单位 | Token，普通输入、输出与缓存输入分别计价 |

## 选择请求协议

<CardGroup cols={2}>
  <Card title="Chat Completions" icon="comments" href="/api-reference/chat-completions">使用 messages 消息列表，读取 choices 中的回复，适合已有聊天应用。</Card>
  <Card title="Responses" icon="code" href="/api-reference/responses">使用 input 输入，遍历 output 消息内容，流式按事件类型处理。</Card>
</CardGroup>

两个协议都支持本页描述的基础文本调用。不要把 Chat 的 `max_completion_tokens`、`reasoning_effort` 直接复制为 Responses 参数；对应写法是 `max_output_tokens` 和 `reasoning.effort`。

## 输出上限与用量

最小联调建议 `reasoning_effort=low`、输出上限 128；复杂业务应提高到合理上限。推理也占用输出额度，达到上限时可能只得到部分文本。

普通账户输入 2 元、输出 10 元、缓存输入 0.10 元／百万 Token；VIP 价格和示例见 [计费说明](/pricing)。不能通过可见字符数推算最终费用。

## 能力范围

目前文档确认范围是基础文本、两种 HTTP 协议及 SSE。工具调用、结构化输出、文件、多模态、上下文上限和 WebSocket 需单独确认。`gpt-6.1-terra` 与 GPT-5.6／GPT-6 新型号现已配置上线，见 [GPT 文本模型](/models/gpt-text)；其真实调用与扩展能力需分别验证。
