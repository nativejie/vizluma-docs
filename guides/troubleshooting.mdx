先确认问题发生在连接、创建、查询还是下载阶段，再决定是否修改参数或重试。生成成功后的下载失败通常不需要重新生成。

## 常见现象速查

| 现象 | 优先检查 | 下一步 |
| --- | --- | --- |
| 返回 HTML 或网页 | 请求是否误发往官网／文档站，是否经过异常代理 | 核对最终 URL 和 Content-Type |
| `404` | 路径、重复 `/v1`、任务 ID | 参照 [API 总览](/api-reference/overview) |
| `401` | Bearer 格式、Key 是否完整及有效 | 修正凭证，避免原样反复重试 |
| `403` 或额度错误 | 账号余额、Key 额度、模型白名单 | 在控制台核对并联系对接人员 |
| `400` | 字段类型、模型 ID、数量及规格 | 精简到相应型号最小示例 |
| `409 idempotency_conflict` | 同一幂等键是否换了内容 | 查原任务；新业务使用新键 |
| `429` | 请求速率、并发、查询频率 | 降低并发，遵循等待提示 |
| 请求超时且没有图片 | 是否已有任务 ID 或响应头 | 查询原任务，勿盲目重发 |
| 查询 `200` 但无图片 | 任务是否仍排队／执行／待确认 | 检查业务状态而非只看 HTTP |
| JSON 保存成 `.png` 打不开 | 保存的是响应 JSON 还是图片字节 | 从 URL 下载或解码 Base64 |
| SSE 内容看起来像乱码／JSON 报错 | 是否整段当 JSON、UTF-8 是否分块解码 | 使用 SSE 解析器 |
| 视频下载失败 | 是否已 `completed`，是否带同账户 Key | 重试下载，保留任务 ID |

## 最小化定位步骤

1. 从服务端执行 [模型查询](/api-reference/models)，确认连通性和 Key 可见范围。
2. 复制对应型号的最小请求，只保留文档已声明的字段。
3. 保存 HTTP 状态、响应头和脱敏响应，不收集完整鉴权头。
4. 已接受的任务保存 ID；对比相同时间的控制台任务与消费记录。
5. 查询结果与费用仍不明确时，按 [支持信息](/guides/support) 提交材料。

模型查询成功只能证明该读取路径正常，不能代替付费生成、素材下载或整个网络链路的验收。

## 图片无结果或尺寸不符

检查 `data[].url` 和 `data[].b64_json` 是否有有效内容；异步图片需从 `result.data` 读取。没有业务结果时不要仅凭 HTTP `200` 标记成功。

下载后使用图片解码器查看实际宽高，而不是用文件名或请求尺寸判断。Gemini 的像素形式 `size` 会映射到比例与规格，不保证逐像素匹配。见 [尺寸与质量](/guides/sizes-and-quality)。

## 获取帮助

准备调用时间和时区、模型、接口路径、HTTP 状态、请求／任务 ID 及脱敏错误。不要附完整 Key、Cookie 或私密素材。具体模板见 [联系支持](/guides/support)。
