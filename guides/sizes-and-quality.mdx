## 从明确的像素尺寸开始

本轮已验证的请求尺寸为：

```json
{
  "size": "1024x1024"
}
```

它在三个已列出的图像模型中均返回了 `1024x1024` PNG。其他尺寸请先按企业开通范围进行小规模联调，不应仅凭参数被接受就认定实际输出尺寸符合要求。

## 尺寸与计费档位

当前网关配置使用 `1k`、`2k`、`4k` 三个计费档位。以下是部分配置映射，**不是这些尺寸都已经通过端到端验收的清单**：

| 像素尺寸示例 | 计费档位 | 本轮验证 |
| --- | --- | --- |
| `1024x1024` | 1K | 三个模型均通过 |
| `2048x2048` | 2K | GPT Image 2 单张上传编辑通过；不代表其他模型／文生图已验收 |
| `2048x1152` | 2K | 待单独联调 |
| `3840x2160` | 4K | 待单独联调 |
| `2160x3840` | 4K | 待单独联调 |
| `2880x2880` | 4K | 待单独联调 |

这些名称是服务的输出规格／计费档位，不表示每条边均为 1024、2048 或 4096 像素。例如，方图的 4K 档位配置示例是 `2880x2880`，不是 `4096x4096`。

## 比例与 resolution 扩展

网关也接受比例形式的 `size` 和分辨率扩展，例如 `size: "16:9"`、`resolution: "2k"`。这是网关扩展，不是所有客户端 SDK 都支持的通用字段。

正式接入优先使用明确的像素 `size`。不要同时提供互相矛盾的像素尺寸与 `resolution`，也不要假定只改 `resolution` 就一定改变实际输出尺寸。非标准尺寸和 `auto` 的输出及计费，需先与对接人员确认。

## quality 等可选参数

`quality`、`background`、`output_format` 等参数的实际可用性仍需按模型和已开通能力验证。当前基础教程不将它们列为三个模型均已验证的稳定参数，也不提供未经验证的透明背景或质量档位承诺。

## 是否原生生成、是否超分

中转转存实现没有添加图片放大、锐化或超分步骤。但仅凭最终图片和输出尺寸，无法确认模型服务内部是否经过超分处理。因此本文档**不承诺未经验证的原生 2K／4K**。
