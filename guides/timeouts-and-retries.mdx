## 生图是长耗时请求

图片生成接口对客户端表现为同步调用：发送一次请求，等待最终图片结果。本轮单张 1K 联调约需 28～30 秒，历史调用也出现过更长耗时。这些是样例观测，不是 SLA 或耗时上限。

本文示例使用：

| 配置项 | 示例值 |
| --- | --- |
| 连接超时 | 15 秒（cURL） |
| 请求总等待上限 | 600 秒 |
| 自动创建重试 | 关闭 |

请同时检查你的 SDK、业务服务、反向代理、负载均衡和应用前端。只提高 HTTP 客户端超时，并不能解决中间代理提前断连的问题。

## 必须使用 API 域名

模型调用使用 `https://api.vizluma.online/v1`。不要将控制台域名 `sub.vizluma.online` 或文档域名 `docs.vizluma.online` 配置为模型 Base URL。

## 不确定结果不等于失败

下列情况都不保证服务端未执行生成：

- 客户端主动取消请求或等待超时。
- 网络断连，未收到完整响应。
- 网关返回等待超时，例如 `504`。

对于已经提交的异步生成任务，请求结束后任务仍可能继续完成并结算。请先查看调用记录；无法判断时，向对接人员提供时间、模型和请求 ID。

<Warning>
  当前文档不提供可供客户端依赖的生图幂等键或按幂等键查询结果的保证。不要假设重复发送相同请求会自动去重，也不要为生图创建请求开启无条件重试。
</Warning>

## 重试建议

| 情况 | 建议 |
| --- | --- |
| `400` 参数错误 | 先修正参数，不重复发送原请求 |
| `401` / `403` | 检查凭证、额度与权限，再决定是否重新提交 |
| `429` | 降低并发、按提示等待；不能确认是否提交成功时先核对记录 |
| `5xx` / 超时 / 断连 | 先确认执行状态，再决定是否重试 |
| 图片下载失败，但生成已成功 | 优先重试下载，不要重新生图 |

## 并发与批量

不要将“网关接受 `n` 最大为 10”理解为“允许无限并发”。`n` 是单次请求的图片数，并发是同时进行的请求数。

当前不承诺不限速、不限并发或已具备严格的客户级并发隔离。生产调用量、峰值并发、排队策略和批量支持，请在企业开通时确认；业务端应使用有界队列控制并发。

## 文本与 SSE 请求

GPT-6.1 Sol 的 [最小示例](/models/overview) 使用 120 秒客户端等待上限，这不是耗时保证。复杂任务、较高输出上限或上游排队可能耗时更长，应按企业约定设置超时；不要直接套用单次短请求的观测速度。

- Chat Completions 流式逐条解析 SSE 的 `data:`，识别 `[DONE]`；需要最终用量时设置 `stream_options.include_usage=true`。
- Responses 流式处理 `response.output_text.delta`，检查最终 `response.completed`，也要处理错误或不完整状态。
- 已收到部分内容后断连，不代表请求未执行或一定不收费。不要从头自动重发，也不要把新的请求当成原请求的续传。
- 文本同样需要控制并发、检查账户额度，并按请求 ID 核对最终记录。重试可能产生新的生成与费用。
