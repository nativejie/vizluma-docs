## API 地址

```text
https://api.vizluma.online/v1
```

生成图片的完整地址为：

```text
POST https://api.vizluma.online/v1/images/generations
```

文本请求使用同一鉴权方式：`POST /v1/chat/completions` 或 `POST /v1/responses`，见 [文本 API](/api-reference/chat-completions)。

如果客户端已将 Base URL 设置为包含 `/v1`，路径只需追加 `/images/generations`，不要产生 `/v1/v1/`。

## 请求头

```http
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

- `YOUR_API_KEY` 是占位符，请在你自己的服务端替换。
- 使用 HTTPS，保持证书校验开启；不要使用 `curl -k`。
- 不要将 API Key 放进 URL、查询参数、提示词或图片文件名。
- 接口调用使用 API Key，不依赖控制台浏览器登录态或 Cookie。

## 环境变量

以下是示意配置，**不要把真实密钥写入代码仓库或公开文档**：

```bash
export VIZLUMA_API_KEY="YOUR_API_KEY"
export VIZLUMA_BASE_URL="https://api.vizluma.online/v1"
```

生产环境应通过部署平台或密钥管理系统注入。手工联调时，也应避免把真实密钥留在共享终端、Shell 历史和录屏中。

<Warning>
  不要在网页前端、公开在线编辑器或第三方文档调试器中粘贴生产 API Key。由你的业务后端调用 Vizluma API，再把业务结果返回前端。
</Warning>

## 密钥失效或泄露

联系管理员禁用受影响的 Key 并更换凭证，同时核对调用记录。排障材料仅保留模型名、时间、HTTP 状态和请求 ID，不要发送完整 Key、密码、Cookie 或完整鉴权请求头。

收到 `401` 时先检查是否漏传 `Bearer`、Key 是否复制完整、是否过期或已被禁用；不要对相同凭证不断重试。其他问题见 [错误处理](/api-reference/errors)。

## 不同凭证的用途

| 凭证 | 用途 | 是否用于模型调用 |
| --- | --- | --- |
| API Key | API 请求与允许的任务查询 | 是，使用 Bearer 请求头 |
| 控制台密码 | 登录账号 | 否 |
| 浏览器登录会话 | 控制台页面访问 | 否 |

API Key 的账号余额、Key 额度、有效期、模型白名单和 IP 限制可能分别影响可用性。先通过 [模型列表](/api-reference/models) 核对可见范围，再对照 [错误处理](/api-reference/errors) 检查失败原因。获取 Key 的步骤见 [账号与 Key](/getting-started/enterprise-access)。

## Claude Messages 请求头

[Claude Messages](/api-reference/messages) 示例使用 `x-api-key: YOUR_API_KEY` 与 `anthropic-version: 2023-06-01`；其余 API 示例继续使用 Bearer 方式。使用同一枚本站 Key，但不要在同一请求中放入两枚不同凭证。模型列表中的 Claude、Terra 或其他新型号仍受账户白名单约束。
